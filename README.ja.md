# pCloud MCP for Cloudflare Workers

[English](README.md) | **日本語**

pCloudに保存したファイルを、ChatGPTなどのMCP対応AIクライアントからCloudflare Workers経由で利用できるようにする、セルフホスト型・読み取り専用のRemote MCPサーバーです。

専用サーバーを常時稼働させず、自分のpCloudアカウントをMCPクライアントへ接続したい人向けのプロジェクトです。各利用者が自分のCloudflare環境へWorkerをデプロイし、自分のpCloud・Cloudflare設定を使用します。

## できること

- MCP上に公開したフォルダを一覧表示する
- ファイル名・フォルダ名・仮想パスを検索する
- ファイルのメタデータを取得する
- 対応するUTF-8テキストファイルを読み取る
- PNG / JPEG画像をMCPの画像コンテンツとして返す
- DOCX / XLSX / PPTXをMCPの埋め込みリソースとして返す
- `PCLOUD_ROOT_PATH` でMCPから見えるpCloudの範囲を特定のサブツリーに限定する

現在のサーバーは、アップロード、削除、移動、名前変更、フォルダ作成、共有などの**書き込み操作を提供しません**。

Cloudflare Workers、OAuth、コマンドライン、MCP設定などに慣れていない場合は、すべての技術要素を先に理解しようとせず、AIコーディングアシスタントにセットアップを案内させる方法を推奨します。

AIアシスタントにこのリポジトリを参照させ、変更を始める前に[手動セットアップガイド](docs/SETUP.md)と[SECURITY.md](SECURITY.md)を読むよう指示してください。シークレットはプロンプト、コミット、Issue、スクリーンショット、ログへ含めず、必要になった時点で信頼できるローカル環境や各サービスのシークレット入力機能から直接入力してください。

そのまま使える指示例：

```text
このpCloud MCPサーバーを自分の環境へセルフホストする作業を手伝ってください。
最初に README.md、docs/SETUP.md、SECURITY.md を読んでください。
```

AIを利用するとインフラ知識の負担は減らせますが、上記のリスクがなくなるわけではありません。デプロイ環境、認証情報、Cloudflare Accessポリシー、pCloudの公開範囲についての最終的な管理責任は利用者にあります。

## 仕組み

```text
MCP対応AIクライアント
        |
        | Remote MCP + OAuth
        v
Cloudflare Access
        |
        | signed Access JWT
        v
Cloudflare Worker
        |
        | pCloud OAuth / API
        v
pCloud
```

各デプロイは利用者自身のCloudflare・pCloud環境を使用します。外部からの認可境界はCloudflare Accessが担い、Worker側でもAccessが付与した署名済みJWTを検証してからpCloudへアクセスします。

## 現在のツール

| Tool | 用途 |
| --- | --- |
| `hello` | 接続確認 |
| `list_folder` | 仮想フォルダの一覧表示 |
| `search_files` | 名前・仮想パスの検索（メタデータのみ） |
| `get_file_info` | 指定した仮想ファイルパスのメタデータ取得 |
| `read_file` | 対応するUTF-8テキストファイルの読み取り |
| `get_image_content` | PNG / JPEGをMCP ImageContentとして返す |
| `get_office_content` | DOCX / XLSX / PPTXを埋め込みMCPリソースとして返す |

## セキュリティモデルの概要

- WorkerのエンドポイントはCloudflare Accessで保護し、Worker側でもAccess JWTを独立して検証します。
- `PCLOUD_ROOT_PATH` により、特定のpCloudサブツリーをMCP上の `/` として公開できます。接続先が必要とする最小限の範囲を設定してください。
- MCPツールは意図的に読み取り専用として設計され、pCloudへの書き込み操作は公開しません。
- リクエスト、上流レスポンス、検索処理、コンテンツサイズ、実行時間にはアプリケーション側の上限があります。
- pCloudから取得したファイルやメタデータは信頼できない入力です。AIクライアントを誘導するプロンプトインジェクションや誤解を招く指示が含まれる可能性があります。
- Cloudflare Accessを迂回する別ルートを同じWorkerへ公開しないでください。

詳細な脅威モデル、認証情報の扱い、脆弱性報告方法は[SECURITY.md](SECURITY.md)を参照してください。実装詳細や正確な安全上限は[docs/DESIGN.md](docs/DESIGN.md)に記録しています。

## 主な利用上の制限

| 機能 | 現在の仕様 |
| --- | --- |
| 検索 | ファイル・フォルダ名と再構築した仮想パスのみ。ファイル本文の全文検索は非対応 |
| テキスト | 対応形式のみ、UTF-8厳格。既定256 KiB、最大1 MiBまで指定可能 |
| 画像 | PNG / JPEG、元ファイル最大5 MiB |
| Office | DOCX / XLSX / PPTX、元ファイル最大1 MiB |
| PDF | 現在のMCPツールでは非対応 |
| 書き込み操作 | 非対応 |

大きなフォルダツリーでは検索上限に達する場合があります。その場合、途中までの不完全な結果が返ることを前提にせず、より狭い `path` を指定してください。

Officeファイルはツール結果内の埋め込みリソースとして返されます。利用するMCPクライアント側が、ツール結果内のembedded resourceを扱える必要があります。
